# Workflow: 매체 운영 자동화 (네이버 입찰/예산 제안 → 대시보드 취합 → 소재 등록)

담당 서브에이전트: `media-ops` (신규, 8번째)
ad-factory는 "소재 제작"까지만 담당(Meta PAUSED 업로드로 종료). 이 workflow는 그 다음 단계 —
**매체 운영(네이버 입찰/예산·크로스채널 리포트·소재 등록)** 을 담당한다.

## INPUT
- 네이버 검색광고 API 키 3종: License Key, Secret Key, Customer ID
  - 미발급 상태라면 Stage 0부터 시작 (아래 참고)
- Meta 광고 계정 (기존 ad-factory/mata_ad 연동 재사용)
- 목표 ROAS/CTR 등 캠페인별 기준값 (없으면 최초 실행 시 사람에게 질문)
- 데이터 로그: `data/media-ops-naver-bid-log.csv`, `data/media-ops-report-log.csv`

## Stage 0. 네이버 검색광고 API 키 발급 확인 (최초 1회, 선행 필수)
1. 네이버 검색광고 관리시스템(https://searchad.naver.com) 로그인
2. 우측 상단 **도구 > API 사용 관리** 이동
3. **네이버 검색광고 API 사용 신청** → 접근 IP 등록(스크립트를 돌릴 서버/PC의 고정 IP 필요) → **인증키 발급**
4. 발급되는 3가지 값을 `scripts/media-ops/.env` 에 저장 (⚠️ 이 파일은 `.gitignore`에 등록되어 있어 커밋되지 않음 — `.env.example` 복사해서 사용)
   - `NAVER_API_LICENSE` (License Key)
   - `NAVER_API_SECRET` (Secret Key)
   - `NAVER_CUSTOMER_ID`
5. ⚠️ 이 키는 광고 계정을 직접 조작할 수 있는 자격증명이다 — Slack/이메일 등 평문으로 공유 금지, `.env` 파일로만 관리

## Stage A. 네이버 입찰가/예산 자동조정 (제안 → 사람 승인 → 적용)
> **원칙**: 실제 광고비가 바로 움직이는 영역이므로, 처음엔 **"제안만 하고 사람이 승인해야 실제 반영"** 방식으로 시작한다.
> 룰 기반 완전자동(승인 없이 즉시 반영)은 이 방식이 몇 주 이상 안정적으로 검증된 뒤에만 검토한다 (CLAUDE.md 주의사항 원칙).

1. `scripts/media-ops/naver_ads_client.py` 로 캠페인/광고그룹/키워드별 최근 성과(노출/클릭/전환/비용) 조회
2. 사람이 사전에 정한 룰(예: `ROAS < 목표치 80% → 입찰가 10% 하향 제안`, `전환 0 + 클릭 20회 이상 → OFF 제안`)을 적용해
   **제안 목록**을 생성 (아직 아무것도 변경하지 않음 — 읽기 전용 조회만 수행)
3. 제안 내역을 `data/media-ops-naver-bid-log.csv`에 상태=`제안`으로 기록, 사람에게 표로 보고
4. 사람이 검토 후 승인한 항목만 골라 CSV 상태를 `승인`으로 변경 (사람이 직접, 또는 팀장이 사람 지시를 받아 대신 표시)
5. **승인된 행만** `scripts/media-ops/apply_approved_bids.py` 로 실제 반영 → 반영 성공 시 상태=`적용완료`로 갱신
6. ⚠️ `승인` 상태가 아닌 행은 절대 반영 스크립트가 건드리지 않는다 (스크립트 자체가 상태 컬럼을 확인 후 필터링)

## Stage B. 크로스채널 대시보드/보고서 취합
1. Meta(`mata_ad` 계열 insight 도구) + 네이버(`naver_ads_client.py`)에서 각각 일/주 단위 성과(노출/클릭/비용/전환/ROAS) 조회
2. 매체별 지표를 공통 스키마로 정규화해 `data/media-ops-report-log.csv`에 적재 (한 행 = 매체+캠페인+일자)
3. V1(현재 단계): 취합 결과를 Markdown 표 리포트로 정리해 사람에게 직접 보고
4. V2(확장, 사람 승인 후 착수): Slack 채널 자동 전송 또는 Google Sheets 자동 업데이트 — 아직 구축하지 않음, 필요해지면 별도 요청으로 진행
5. 리포트에는 반드시 "데이터 기준 기간", "매체별 갱신 시각"을 명시해 오래된 데이터로 착각하지 않게 한다

## Stage C. 소재 등록 자동화 (네이버, 전 매체 일괄의 1단계)
1. ad-factory가 이미 생산한 소재(`data/ad-factory-script-bank.csv`, 상태=`생성완료`)를 네이버 광고 규격(검색광고 텍스트 소재 / GFA 배너 규격)으로 변환
2. `naver_ads_client.py` 로 광고그룹에 소재 등록
3. ⚠️ **신규 등록되는 캠페인/광고그룹/키워드는 반드시 '중지(OFF)' 상태로 생성** — Meta의 PAUSED 규칙과 동일한 원칙.
   네이버 API에서 캠페인 상태값은 `userLock: true` 또는 상태 필드를 OFF로 명시 (정확한 필드명은 Stage 0 키 발급 후 공식 문서로 재검증 필요 — 아래 "검증 필요" 참고)
4. 등록 완료 시 `data/ad-factory-script-bank.csv`의 해당 소재 상태를 `PAUSED업로드`로 갱신 (Meta와 동일 상태값 재사용)
5. 카카오모먼트/구글애즈는 이번 범위에서 제외 — 필요해지면 별도 workflow로 확장

## VALIDATE
- [ ] Stage A: 사람이 `승인`으로 표시하지 않은 행이 실제로 반영되지 않았는가
- [ ] Stage A: 모든 제안에 "제안 사유"(어떤 룰이 트리거됐는지)가 CSV에 함께 기록됐는가
- [ ] Stage B: 리포트에 데이터 기준 기간이 명시됐는가
- [ ] Stage C: 신규 등록된 네이버 캠페인/광고그룹이 전부 OFF(중지) 상태인가 — ON 상태로 등록된 것이 하나라도 있으면 실패
- [ ] `.env` 파일이나 API 키가 커밋되거나 사람에게 평문으로 노출되지 않았는가
- [ ] 광고비 집행에 영향을 주는 모든 액션(입찰가 변경, 예산 변경, 캠페인 ON 전환)이 사람 승인 기록과 함께 이뤄졌는가

## ⚠️ 검증 필요 (실제 키 발급 후 재확인할 것)
`naver_ads_client.py`의 엔드포인트 경로·필드명은 네이버 검색광고 오픈API 공식 문서 기준으로 작성했지만,
실제 라이브 키로 최초 실행 시 아래를 반드시 재확인한다:
- 인증 서명 방식(HMAC-SHA256) 및 헤더명이 최신 문서와 일치하는지
- 캠페인/광고그룹 상태 필드명과 OFF 상태값이 정확한지
- GFA(배너)는 검색광고와 인증 체계가 달라 별도 OAuth 연동이 필요 — 이번 1차 구축은 검색광고 텍스트 소재까지만, GFA는 후속 확장
