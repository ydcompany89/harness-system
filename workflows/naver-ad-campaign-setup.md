# Workflow: 네이버 스마트스토어 광고 캠페인 세팅 (브라우저 자동화)

담당 서브에이전트: `media-ops` (Stage D — `workflows/media-ops-automation.md` Stage A/B/C의 확장)

`media-ops-automation.md`의 Stage A/C는 **네이버 검색광고 오픈API**(`naver_ads_client.py`)를 전제로 한다.
API 키가 아직 없을 때(Stage 0 미완료)는, 이 workflow로 **Claude in Chrome 브라우저 자동화**를 통해
네이버 광고센터 UI를 직접 조작해 캠페인/광고그룹/소재를 세팅한다. API 키가 발급되면 반복 실행 구간(입찰가 자동조정 등)은
`media-ops-automation.md` 쪽 API 스크립트로 점차 이관한다.

⚠️ 실행 전 `chrome-browser` 스킬을 먼저 로드한다 (Claude in Chrome 확장, 사용자의 실제 로그인 세션 사용).
로그인 자체·비밀번호·인증번호는 **절대 추측하거나 대신 입력하지 않는다** — 로그인 안 돼 있으면 사람에게 직접 로그인을 요청한다.

## INPUT
- 상품명, 스마트스토어 상품 링크
- 키워드 목록 + (있으면) 키워드별 우선순위/입찰가
- 상품 카테고리 (없으면 Stage 2~3에서 확인)
- 데이터 로그: `data/media-ops-naver-campaign-log.csv`, `data/media-ops-naver-negative-keywords.csv`

## PROCESS

### Stage D-1. 로그인 확인
네이버 광고센터 로그인 상태를 먼저 확인한다. 로그인 안 돼 있으면 사람에게 직접 로그인을 요청하고 대기한다.
인증정보(비밀번호/인증번호)를 추측·자동 생성하지 않는다.

### Stage D-2. 키워드 분석 & 등급 분류
아래 7개 기준으로 각 키워드를 평가한다: 검색량 / 기본 전환율 / 상품 적합도 / PC 쇼핑탭 대표 카테고리 /
경쟁 정도 / 현재 광고 노출 위치 / 기존 광고 데이터(클릭·비용·전환, 있는 경우).

등급: **A=메인 키워드 / B=서브 키워드 / C=테스트 키워드**

| 키워드 | 등급 | 검색량 | 적합도 | 카테고리 | 경쟁도 | 권장 입찰가 |
|---|---|---|---|---|---|---|

⚠️ 확인되지 않는 항목은 절대 추측하지 말고 `확인 필요`로 표기한다.

### Stage D-3. PC 쇼핑탭 카테고리 확인
각 키워드를 네이버 PC 쇼핑탭에서 검색해 상위 노출 상품의 카테고리를 확인한다.
상품 실제 카테고리와 크게 다르면 `카테고리 적합성 확인 필요`로 표시 (임의로 맞춰서 보고하지 않는다).

### Stage D-4. 캠페인 생성
상품 1개당 캠페인 1개 원칙. 이미 해당 상품 캠페인이 있으면 새로 만들지 않고 기존 캠페인을 재사용한다.

### Stage D-5. 광고그룹 생성 (키워드별 분리)
키워드별로 광고그룹을 분리하고, 그룹명에 핵심 키워드가 드러나게 한다 (예: `01_침대받침대`, `02_매트리스받침대`).

### Stage D-6. 동일 상품 소재 등록
각 광고그룹에 동일 상품 소재를 등록한다. **이미 동일 소재가 있으면 중복 등록하지 않는다.**
등록 후 반드시 상품 ID를 확인해 기록한다.

### Stage D-7. 노출용 상품명 설정
광고그룹의 핵심 키워드를 자연스럽게 포함한 노출용 상품명을 만든다. 원칙:
- 실제 상품 특성을 벗어나지 않는다
- **허위·과장 표현 금지** (ad-factory의 표시광고법 필터 원칙과 동일 — "최고/유일/100%/무조건" 등 단정 표현 배제)
- 동일 상품명 반복 금지, 키워드만 억지로 나열 금지
- 네이버 광고센터가 현재 허용하는 글자 수/정책을 실행 시점에 확인 (버전에 따라 바뀔 수 있어 매번 확인)

### Stage D-8. 입찰가 설정
사람이 기준을 제공했으면 그 기준을 우선 적용. 기준이 없으면 경쟁 데이터/기존 성과로 **"권장 입찰가"를 먼저 제시**만 하고,
⚠️ **광고비가 실제로 변하는 변경은 초기에는 반드시 사람 승인 후 실행** (media-ops-automation.md Stage A와 동일 원칙).

### Stage D-9. 광고 노출 확인
설정 완료 후 각 핵심 키워드의 노출 여부를 확인한다 (가능하면 광고센터의 노출 현황 진단 기능 활용).
기록 항목: 키워드 / 입찰가 / 노출 여부 / 예상·확인 위치 / 미노출 사유 / 확인 시간

### Stage D-10. 검색어 & 제외검색어 관리
실제 검색어를 4분류: ① 핵심 관련 ② 확장 가능 ③ 관련성 낮음 ④ 명확한 제외 대상.
제외 필요 검색어는 `data/media-ops-naver-negative-keywords.csv`에 후보로 기록하고, **네이버 제외검색어 한도를 실행 시점에 확인**해
한도를 넘기지 않게 관리한다 (한도 초과분은 우선순위 낮은 것부터 보류, 사람에게 보고).

### Stage D-11. 성과 분석
가능한 데이터 수집: 노출수/클릭수/CTR/광고비/평균클릭비용/전환수/전환율/매출/ROAS/검색어.
키워드별 표로 비교 (`data/media-ops-report-log.csv`에도 정규화 적재 — media-ops-automation.md Stage B와 동일 로그 재사용).

### Stage D-12. 최적화 제안
성과 기반 개선안: ① 입찰가 조정 ② 유지 키워드 ③ 확대 검토 ④ 제외 검토 ⑤ 신규 광고그룹 후보 ⑥ 노출용 상품명 수정 후보.
⚠️ **광고비가 증가하는 변경은 제안만 하고 자동 실행하지 않는다** — 반드시 사람에게 먼저 보여준다.

## 작업 안전 규칙 (실행 전 사람 승인 필수)
- 대규모 광고그룹/소재 삭제
- 캠페인 삭제
- 광고비가 크게 증가하는 입찰가 변경
- 예산 증액
- 광고 ON/OFF 대규모 변경

단순 조회/검색/데이터 정리/중복 확인은 자동으로 수행해도 된다.

## VALIDATE
- [ ] Stage D-1: 로그인/인증정보를 추측하거나 대신 입력하지 않았는가
- [ ] Stage D-2~3: `확인 필요`로 남겨야 할 항목을 임의로 추정해서 채우지 않았는가
- [ ] Stage D-6: 동일 소재 중복 등록이 없는가
- [ ] Stage D-7: 노출용 상품명에 허위·과장 표현이 없는가, 글자 수/정책을 실행 시점에 재확인했는가
- [ ] Stage D-8, D-12: 광고비가 실제로 늘어나는 변경을 사람 승인 없이 실행하지 않았는가
- [ ] Stage D-10: 제외검색어 한도를 초과하지 않았는가
- [ ] "작업 안전 규칙" 5개 항목 중 사람 승인 없이 실행된 것이 없는가
- [ ] 결과가 `data/media-ops-naver-campaign-log.csv` / `data/media-ops-naver-negative-keywords.csv`에 로깅됐는가

## 작업 결과 보고 형식
```
[작업 결과]
상품: / 캠페인:
생성 광고그룹: 총 __개 / 등록 소재: 총 __개
노출용 상품명: __개 설정 완료 / 입찰가: __개 설정 완료
확인 필요: __건 / 오류: __건
```
표: `광고그룹 | 핵심 키워드 | 노출용 상품명 | 입찰가 | 상태`
마지막에 문제점과 사람 승인이 필요한 사항을 별도로 표시한다.
